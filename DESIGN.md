# Grand Pattern Fibonacci Dual-Direction Architecture

## Overview
A cellular graph of rooms with dual vector databases, JEPA predictive mapping, double-entry bookkeeping, spectral vibe computation, three-phase garbage collection, and murmur gossip dissemination. Built in pure Rust with zero external dependencies.

## Core Architectural Choices

### 1. Zero Dependencies
We rely exclusively on `std` and `core`. This eliminates supply-chain risk, ensures reproducible builds, and forces us to implement every abstraction ourselves—yielding deeper understanding and tighter integration.

### 2. Const Generics for Dimensionality
All vector spaces, matrices, and buffer sizes are parameterized via const generics (`const DIM: usize`, `const CAP: usize`). This pushes bounds checking and allocation sizing to compile time, eliminates heap fragmentation for fixed-size structures, and enables monomorphized SIMD dispatch.

### 3. SIMD via `std::simd`
Vector operations use `std::simd::Simd<f32, LANES>` with const-generic lane selection. We fall back to scalar loops when `DIM % LANES != 0`, ensuring the architecture works for any dimension while still accelerating the hot path.

### 4. Arena-Based Room Allocation
Rooms live in a single contiguous `Vec<Room>` inside the `Graph`. Room references are lightweight `RoomId` indices rather than pointers. This improves cache locality, simplifies serialization, and makes garbage collection non-moving (we only clear edges and vectors, not relocate rooms).

### 5. Dual Vector DBs: Z_in and Z_out
Each room maintains two ring buffers:
- **Z_in (Perception)**: Observations arriving from neighbors or sensors.
- **Z_out (Prediction)**: Anticipated future states generated by the room’s JEPA mapper.
Both are fixed-capacity, overwriting oldest vectors when full. This models biological short-term memory and ensures bounded memory per room.

### 6. JEPA Mapping
Joint Embedding Predictive Architecture is realized as a learnable affine transform with online momentum updates. Each room stores a weight matrix `W` and bias `b`. Training minimizes the contrastive prediction error between `Z_out` embeddings and actual future `Z_in` vectors. No backpropagation graph is built; updates are Hebbian-like local rules.

### 7. Double-Entry Bookkeeping
Every inter-room interaction is recorded as an immutable transaction with two legs: debit and credit. The ledger is append-only, providing full provenance for vibe redistribution and GC reachability analysis. Accounts are identified by `RoomId` pairs.

### 8. Vibe Computation
"Vibe" is the spectral energy of a room, computed as the exponential moving average of L2 norms across `Z_in` and `Z_out`, modulated by ledger transaction volume. High-vibe rooms propagate influence faster in gossip; low-vibe rooms become GC candidates.

### 9. Three-Phase Garbage Collection
- **Mark**: Traverse from high-vibe root rooms, marking reachable rooms and active edges.
- **Sweep**: Zero out unreachable rooms’ vectors, reset their ledgers, and recycle their IDs into a free list.
- **Compact**: Coalesce fragmented edge lists and rebalance ring-buffer pointers so that active data is contiguous.

### 10. Murmur Gossip
An epidemic protocol with Fibonacci backoff. Rooms gossip their `Z_out` predictions and vibe levels to random neighbors. The Fibonacci sequence determines inter-gossip intervals, creating a natural rhythm that reduces network contention while still guaranteeing eventual consistency in connected components.

### 11. Fibonacci Topology
The cellular graph grows according to Fibonacci adjacency: new rooms connect to the two previous rooms in creation order. This yields a sparse, scale-free-like structure with small-world properties, all without randomness in topology generation.

## Module Map
- `simd`: SIMD-accelerated vector and matrix primitives.
- `vector_db`: Ring-buffer dual vector databases (`ZSpace`).
- `jepa`: Predictive mapping between embeddings.
- `ledger`: Double-entry transaction log.
- `vibe`: Spectral energy and decay computation.
- `gc`: Three-phase mark-sweep-compact collector.
- `gossip`: Murmur epidemic broadcast with Fibonacci scheduling.
- `room`: Cellular node containing all subsystems.
- `graph`: Arena allocator and topology manager.
- `lib`: Public API and integration harness.

## Testing Strategy
Every module has unit tests. Integration tests verify end-to-end graph construction, JEPA convergence, GC correctness, and gossip saturation. We target 15+ tests covering edge cases like zero-dimensional rooms, full ring buffers, and Fibonacci overflow.
